# 名字的味道 Name Your Flavor

純前端、免後端的姓名美食配對網站。輸入中文、英文或日文姓名，探索一道代表料理、四道延伸推薦、食材與風味筆記，以及姓名字典命中線索。可將配對結果下載為 PNG 圖片。姓名只在目前瀏覽器分頁中處理，不會傳送或儲存。

> 配對結果由文字意象與固定演算法產生，僅供娛樂及美食探索，不代表人格、健康或營養判斷。

## 本機執行

使用 Python 提供靜態檔案服務：

```sh
python -m http.server 8080
```

瀏覽 `http://localhost:8080`。Windows 使用者也可以在專案資料夾雙擊 `start-local.bat`，並保持啟動視窗開啟。不要直接雙擊 `index.html`：瀏覽器會基於安全限制阻擋 `file://` 頁面的 ES modules，網站也會顯示啟動提示。

## 部署

### Cloudflare Pages

1. 將專案推送至 GitHub 或 GitLab 儲存庫。
2. 在 Cloudflare Pages 建立專案並連結儲存庫。
3. Framework preset 選擇 `None`，Build command 留空，Build output directory 設為 `.`（專案根目錄）。
4. 部署後即可使用；不需要環境變數、建置程序或伺服器。

### GitHub Pages

1. 將專案檔案推送到儲存庫的 `main` 分支。
2. 在儲存庫的 **Settings → Pages** 選擇從 `main` 分支根目錄部署。
3. 等待 GitHub Pages 發佈網站。若發佈於專案子路徑，頁面與模組都使用相對路徑，可直接運作。

## 字典與美食資料

- `js/dictionary.js` 的 `NAME_DICTIONARY` 收錄超過 500 個不重複中英文關鍵字，涵蓋自然、植物、色彩、品德、情感、質感、季節與英文名字等意象，並定義味覺／口感／菜系／料理方式權重及食材線索。多字詞會優先匹配，避免重複計入其內部單字；英文詞以單字邊界匹配。
- `js/foods.js` 的 `FOODS` 由 `rows` 資料列產生，目前提供 130 多道料理。新增料理時提供唯一 ID、名稱、emoji、菜系、分類、味覺／口感類型、料理方式、食材、固定過敏原列舉、飲食類型及辣度。emoji 與 CSS 插圖是本地視覺素材，不需外部圖片。
- 過敏原代碼列於 `ALLERGENS`；若新增代碼，請同步更新資料完整性測試及介面上的排除選項。
- `css/style.css` 集中管理版面、色彩、響應式斷點與減少動態效果的設定。
- `js/result-image.js` 使用 Canvas 在瀏覽器本機繪製配對結果圖片；不會上傳姓名或呼叫外部圖片服務。

## 演算法

姓名正規化依序去除首尾空白、合併連續空白、使用 Unicode NFKC 將全形字元標準化、轉小寫、將片假名轉為平假名，並只移除尾端稱謂。正規化後必須是 1–20 個 Unicode 字元且含有文字或數字。

`js/hash.js` 使用規格中的固定多序列雜湊。命中字典時以命中權重建立偏好；沒有命中時由雜湊建立基礎偏好。每道美食依序以味覺 30%、口感 20%、菜系 15%、料理方式 15%、食材 10%、固定雜湊 10% 計分。飲食、辣度和過敏條件只排除不適合的選項，不改變姓名雜湊。代表料理取最高分，推薦採不同料理分類優先，且不重複。

分享連結包含姓名、飲食類型、辣度及版本，不包含過敏條件。載入帶有 `name` 的分享連結會自動重建結果。

## 測試

需要 Node.js（不安裝套件）：

```sh
node --experimental-default-type=module tests/run-tests.mjs
```

測試包含姓名正規化、稱謂結尾比對、字典優先與英文單字邊界、固定結果、飲食過濾、至少 120 道美食與 500 個不重複字典關鍵字的資料完整性、推薦多樣性及 HTML 樣式輸入安全性。

## 隱私、安全與授權

- 不含後端、分析工具、追蹤程式或外部資料請求；內容完全在瀏覽器中處理。
- 姓名輸出使用 `textContent`；頁面設定 Content Security Policy，並以 `connect-src 'none'` 禁止網路連線。
- 網站不儲存姓名；分享時只有使用者主動按下分享按鈕才會產生連結。
- 食物圖示使用 Unicode emoji、CSS 漸層及系統字型；未使用來源不明的外部圖片或字型。
